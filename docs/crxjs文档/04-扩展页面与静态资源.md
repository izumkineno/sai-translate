# 04 — 扩展页面与静态资源

> 来源：`packages/vite-plugin-docs/docs/concepts/01-pages.md`、`03-content-scripts.md#Static Assets / HTML in content scripts`、`common/_get-url-for-images.mdx`、`src/node/plugin-manifest.ts`、 `src/node/plugin-webAccessibleResources.ts`、`src/node/plugin-fileWriter*.ts`

## 1. 哪些算「扩展页面」

CRXJS 把 **manifest 能声明的 HTML** 与 **额外 HTML** 区分处理：

| 类型 | 声明位置 | 本模板实例 |
|---|---|---|
| Action Popup | `action.default_popup` | `src/popup/index.html` |
| Side Panel | `side_panel.default_path` | `src/sidepanel/index.html` |
| Options | `options_page` / `options_ui.page` | 本模板未用，按需加 |
| DevTools | `devtools_page` | 同上 |
| Welcome / Onboarding 等 | `vite.config.build.rollupOptions.input` | 未用，示例见下 |

`01-pages.md#Extra HTML pages`：manifest 未覆盖的页面需在 Vite 侧显式声明：

```ts
export default defineConfig({
  build: { rollupOptions: { input: { welcome: 'pages/welcome.html' } } }
})
```

开发期由 Vite dev server 直出，生产期由 Rollup 优化并拷贝到 `dist/`。

## 2. HTML 模板的固定写法

`src/popup/index.html` / `src/sidepanel/index.html` 均为：

```html
<!doctype html>
<html lang="en">
  <head><meta charset="UTF-8" /></head>
  <body>
    <div id="root"></div>
    <script type="module" src="./index.tsx"></script>
  </body>
</html>
```

- 入口脚本必须是 `type="module"`，路径相对 HTML 文件（`./index.tsx`）
- `index.tsx` 负责 `render(() => <App />, root)`，首行 `/* @refresh reload */` 启用 Solid/ React HMR 客户端

## 3. 静态资源 import

`03-content-scripts.md#Static Assets` + `common/_get-url-for-images.mdx` 核心结论：

```ts
import logo from './logo.png'
const url = chrome.runtime.getURL(logo) // content script 必须转扩展 URL
// popup / sidepanel 可直接 <img src={logo} />
```

- **Popup/SidePanel**：与普通 Vite 项目一致，直接 `import` 即可，Vite 负责 hash 与拷贝
- **Content Script**：`import` 的值是**宿主页面 origin 下的 URL**，需 `chrome.runtime.getURL` 转为 `chrome-extension://<id>/assets/logo.xxx.png`
- 框架差异见 `common/ImageCodeBlock.js`：React/Vue/Solid 均用 `chrome.runtime.getURL('icons/logo.png')`，Vanilla 用字符串拼接

插件自动将 content script 依赖加入 `web_accessible_resources`（`plugin-webAccessibleResources`），无需手写；若在 content script 中 `import html from './page.html?raw'` 仅作字符串片段，则**不需**声明 WAR。

## 4. `web_accessible_resources` 自动生成

- **自动**：content script `js` 条目 `import` 的静态资源（图片、字体、CSS）→ 插件推入 `manifest.web_accessible_resources[]`
- **手动**：iframe 注入的扩展页面需显式声明（`03-content-scripts.md#HTML in content scripts`）：

```json
{
  "web_accessible_resources": [{
    "resources": ["pages/iframe.html"],
    "matches": ["https://*.google.com/*"]
  }]
}
```

并同时加入 `build.rollupOptions.input`（同 §1）。

`defineDynamicResource` 适用于 `chrome.scripting.*` 动态注册的脚本资源，内部用占位符 `"<dynamic_resource>"` 延迟展开。

## 5. 公共资源与输出

- `public/` 目录（如 `public/logo.png`）由 `plugin-fileWriter_public.ts` 原样拷贝到 `dist/`，路径保持 `public/` 前缀剥离后的相对路径
- `assets/` 下的 `vite.svg / solid.svg / crx.svg` 通过 `import` 被 Vite 处理，输出带 hash 到 `dist/assets/`
- 开发期：HTML 由 dev server 直出；content script 由 `fileWriter` 以 Rollup 二次打包写入 `dist/` 并通过 dev-loader 注入

## 6. 本模板的资源映射

```
public/logo.png        → dist/public/logo.png  (或 dist/logo.png，取决于 publicDir 配置)
src/assets/*.svg       → dist/assets/*.svg (hash)
src/popup/index.html   → dist/src/popup/index.html (+ 单独的 js/css chunk)
src/sidepanel/index.html → dist/src/sidepanel/index.html
```

`manifest.config.ts` 引用 `public/logo.png` 在构建后会被 `pluginManifest` 重写为实际 asset 文件名（`renderCrxManifest` 阶段）。
