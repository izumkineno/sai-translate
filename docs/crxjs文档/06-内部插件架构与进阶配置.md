# 06 — 内部插件架构与进阶配置

> 来源：`src/node/index.ts`（插件组装顺序）、`src/node/types.ts`（CrxOptions / CrxPlugin 扩展钩子）、`src/node/plugin-*.ts` 系列、`fileWriter*.ts`、`helpers.ts`、`CHANGELOG 2.5–2.7`

## 1. 插件总览（16 子插件，顺序敏感）

`src/node/index.ts#crx()` 返回 `PluginOption[]`：

```ts
export const crx = (options): PluginOption[] => [
  pluginOptionsProvider(options),        // 0. 统一配置入口，解析 manifest（函数/对象/Promise）
  pluginExtensionCors(),                  // 1. 自动放行 chrome-extension:// / moz-extension://
  pluginContentScriptsIife(),             // 2. 必须早于 manifest，决定 IIFE 判定
  pluginBackground(),                     // 3. service-worker-loader 生成
  pluginContentScripts(),                 // 4. 内容脚本主逻辑（finalizeBuildContentScripts）
  pluginDeclaredContentScripts(),         // 5. manifest 声明式 content_scripts
  pluginDynamicContentScripts(),          // 6. ?script / ?iife / standaloneFiles 动态脚本
  pluginFileWriter(),                     // 7. 开发期 Rollup 二次打包写入 dist
  pluginFileWriterPublic(),               // 8. public/ 原样拷贝
  pluginFileWriterPolyfill(),             // 9. 旧浏览器 polyfill 注入（custom-elements）
  pluginHtmlInlineScripts(),              // 10. HTML 内联脚本处理
  pluginWebAccessibleResources(),          // 11. WAR 自动生成
  pluginContentScriptsCss(),              // 12. CSS 提取为 synthetic 虚拟模块
  pluginHMR(),                            // 13. HMR 装饰与 runtime-reload
  pluginManifest(),                       // 14. manifest 两阶段变换（transform/render）
  pluginPrint(),                          // 15. 构建完成打印输出清单
].flat()
```

> `pluginContentScriptsIife` 必须在 `pluginManifest` 之前，否则 `isIifeContentScript` 标志未就绪会导致输出文件名错误（`index.ts` 注释）。

## 2. 各插件职责

| 插件 | 文件 | 作用 |
|---|---|---|
| optionsProvider | `plugin-optionsProvider.ts` | 归一化 `CrxOptions` + `ManifestV3Export`，供其它插件 `getOptions(config)` |
| extensionCors | `plugin-extensionCors.ts` | 兼容 Vite 4.5.6/5.4.12/6.0.9+ 的 localhost-only CORS 默认，自动 `server.cors.origin += chrome-extension://` |
| contentScriptsIife | `plugin-contentScripts_iife.ts` | `.iife.*` 与 `standaloneFiles` → `type: 'iife'`，Rollup 打为自包含 IIFE |
| background | `plugin-background.ts` | 开发/生产 loader 生成，`service_worker` 重写 |
| contentScripts | `plugin-contentScripts.ts` | 协调 declared/dynamic 的公共逻辑，完成构建时脚本收束 |
| declaredContentScripts | `plugin-contentScripts_declared.ts` | 处理 `manifest.content_scripts[].js/css` 的虚拟 CSS 入口注册 |
| dynamicContentScripts | `plugin-contentScripts_dynamic.ts` | 处理 `import "x?script"` 等查询式脚本与 `defineDynamicResource` |
| fileWriter | `plugin-fileWriter.ts` + `fileWriter.ts` | 开发期以 Rollup 二次打包写入 `dist/`，`start/update/write` 三 API |
| fileWriterPublic | `plugin-fileWriter_public.ts` | `publicDir` 拷贝，监听 public 文件变动 |
| fileWriterPolyfill | `plugin-fileWriter-polyfill.ts` | 注入 `@webcomponents/custom-elements` 兼容非 Chromium |
| htmlInlineScripts | `plugin-htmlInlineScripts.ts` | 提取/重写 HTML 内联 `<script>` |
| webAccessibleResources | `plugin-webAccessibleResources.ts` | content script 静态依赖自动加入 WAR，处理 `browser_specific_settings` |
| contentScriptsCss | `plugin-contentScripts_css.ts` | 将 `content_scripts[].css` 转为虚拟模块以享受 HMR |
| hmr | `plugin-hmr.ts` | 装饰 `server.ws.send`，分发 `crx:runtime-reload` / `crx:content-script-payload`，虚拟模块（UnoCSS/Tailwind）特殊处理 |
| manifest | `plugin-manifest.ts` | `transformCrxManifest` / `renderCrxManifest` 两阶段、loading-page 中间件、stub 输入处理 |
| print | `plugin-print.ts` | 构建后终端打印 `dist/` 清单与提示 |

## 3. CrxOptions 全量

`src/node/types.ts#CrxOptions`：

```ts
interface CrxOptions {
  contentScripts?: {
    preambleCode?: string | false  // 注入 content script 前置代码，false 关闭
    hmrTimeout?: number            // HMR 超时 ms
    injectCss?: boolean            // 是否注入 CSS（默认 true）
    standaloneFiles?: string[]      // 强制 IIFE 的文件列表（不依赖 .iife 命名）
  }
  globOptions?: GlobOptions         // tinyglobby 配置
  browser?: 'chrome' | 'firefox'  // 影响 background 输出形态与 WAR
  liveReload?: boolean            // 默认 true，false 时禁用所有自动 reload/HMR 推送
}
```

使用示例：

```ts
crx({
  manifest,
  browser: 'firefox',
  liveReload: false, // 注入型 content script 有副作用时
  contentScripts: {
    preambleCode: 'console.log("injected")',
    standaloneFiles: ['src/injected.ts'],
  },
})
```

## 4. 扩展钩子（给自定义插件用）

`CrxPlugin extends VitePlugin` 新增：

```ts
transformCrxManifest?(manifest: ManifestV3) // transform 阶段，可改 manifest
renderCrxManifest?(manifest, bundle)         // generateBundle 前，可改输出
renderCrxDevScript?(code, script: CrxDevScriptId) // dev 写入前改 content script 代码
```

可用于自定义图标压缩、权限裁剪、内容脚本代码混淆等。

## 5. FileWriter 深入

- **RxJS 管线**：`start$` / `fileWriterEvent$` / `serverEvent$` / `close$` + `outputFiles: Map<string, OutputFile>`
- **增量写入**：`update(id)` 解析 `/src/entry.ts?import` 等 query 变体，`queueWrite` 串行化避免并发写冲突
- **Rolldown 兼容**：`getRollupInputOptions` 过滤 `platform/resolve/transform/moduleTypes/...` 等 Rolldown 专属选项，避免 `Unknown input options: platform` 警告（`CHANGELOG 2.7.1`）
- **产出**：开发期 `dist/` 含 `manifest.json`、`service-worker-loader.js`、`assets/*`、`content-script-loader` 等；`loading-page.html` + `/@crx/dev-ready?path=xxx` 轮询确保 HTML 就绪后再加载

## 6. 常见进阶问题

| 问题 | 根因 | 解法 |
|---|---|---|
| `plugins is not iterable` | Rolldown Vite 的 `buildStart` 不传 `options.plugins` | 已在 `plugin-manifest.ts#configResolved` 兼容，无需处理 |
| `Unknown input options: platform` | Vite 8 透传 Rolldown 选项给 Rollup | 已在 `fileWriter.ts#getRollupInputOptions` 过滤 |
| CORS 被拦 `chrome-extension://` | Vite ≥4.5.6 默认仅 localhost | `pluginExtensionCors` 已自动放行，或显式 `server.cors.origin: [/chrome-extension:\/\//]` |
| CSS 改动不热更 | UnoCSS/Tailwind 虚拟模块 | `plugin-hmr.ts` 2.5.0 后特殊处理 `/@id/__x00__`，确保更新虚拟 CSS |
| Windows 输出文件名含冒号 | 绝对路径转文件名 | `sanitizeFilename` 已处理（2.5.0） |
| 想用动态 `chrome.scripting.registerContentScripts` | 需声明 WAR 占位符 | `defineDynamicResource({ matches })` + `?script` 或 `standaloneFiles` |
