# 07 — 模板项目入口与文件职责（sai-translate）

> 基于仓库当前快照（`vite 8.0.0 / @crxjs/vite-plugin 2.4.0 / vite-plugin-solid 2.11.11 / solid-js 1.9.11`）梳理，覆盖**所有**配置文件与源码入口的职责、调用链与改动指引。

## 1. 顶层一览

```
sai-translate/
├── package.json            # 脚本与依赖，type:module 必需
├── vite.config.ts          # Vite + CRXJS 总装配
├── manifest.config.ts      # 扩展声明（defineManifest）
├── tsconfig.json           # 引用分包（app / node）
├── tsconfig.app.json       # 源码（src/）编译配置
├── tsconfig.node.json      # 构建工具（vite.config.ts）编译配置
├── public/logo.png         # 公共静态资源（由 fileWriterPublic 原样拷贝）
├── docs/                   # 本次新增的 01-07 CRXJS 文档集
└── src/
    ├── popup/              # 工具栏弹窗（action.default_popup）
    ├── sidepanel/          # 侧边栏（side_panel.default_path，Chrome 114+）
    ├── content/            # 内容脚本（注入宿主页面）
    ├── components/         # 跨页面复用组件
    └── assets/             # 被 import 的静态资源（走 Vite 管线，带 hash）
```

## 2. 配置文件逐一说明

| 文件 | 作用 | 关键行 | 改动指引 |
|---|---|---|---|
| `package.json` | 声明 `dev/build/preview`，依赖 `solid-js / @crxjs/vite-plugin / vite-plugin-solid / vite-plugin-zip-pack` | `type: module`、`@crxjs/vite-plugin@^2.4.0` | 升级 CRXJS 直接 `npm i -D @crxjs/vite-plugin@latest`，注意 `CHANGELOG` 的 Vite 8 兼容 |
| `vite.config.ts` | 组装插件流水：`solid() → crx({ manifest }) → zip(...)`，别名 `@`，放行 `chrome-extension://` | `solid()` 必须在 `crx()` 前；`zip({ outDir: 'release', outFileName: 'crx-${name}-${version}.zip' })` | 新增页面：在 `manifest.config.ts` 加声明即可，无需改此文件；需额外 HTML 再加 `build.rollupOptions.input` |
| `manifest.config.ts` | 唯一入口，`defineManifest` 包裹后被 `plugin-optionsProvider` 解析 | `defineManifest({ manifest_version:3, action.default_popup, content_scripts, side_panel, permissions })` | 加 background：`background: { service_worker: 'src/background.ts', type: 'module' }`；加 options：`options_page/ui` |
| `tsconfig.json` | 仅作 `references` 聚合 | `references: [tsconfig.app.json, tsconfig.node.json]` | 无需常改 |
| `tsconfig.app.json` | `src/` 源代码：`jsx:preserve + jsxImportSource:solid-js`、`paths@→src/*`、`types:[vite/client, @crxjs/vite-plugin/client, chrome]` | `noEmit:true + isolatedModules:true` | 新增路径别名同步改 `vite.config.ts#resolve.alias` |
| `tsconfig.node.json` | `vite.config.ts` 自身：`target ES2022 + lib ES2023` | `include: ["vite.config.ts"]` | 若 `manifest.config.ts` 需类型检查，加入 `include` |

## 3. 源码入口链路

### 3.1 Popup（`action.default_popup`）

```
src/popup/index.html  --[script src="./index.tsx"]--> src/popup/index.tsx --[render]--> src/popup/App.tsx --[uses]--> src/components/HelloWorld.tsx
         │                                                        │
     由 Vite HMR 直出                               import crx.svg / solid.svg / vite.svg → dist/assets/*.svg
```

- `index.html`：仅含 `<div id="root">` + module script，CRXJS 开发期由 dev server 直出，生产期由 Rollup 打包
- `index.tsx`：`/* @refresh reload */` + `render(() => <App />, root)`，标准 Solid 入口
- `App.tsx`：展示三 logo + `HelloWorld`，`HelloWorld` 内含 `createSignal` 计数器用于验证 HMR
- `index.css / App.css`：局部样式，HMR 时热更不丢计数器状态

### 3.2 SidePanel（`side_panel.default_path`）

```
src/sidepanel/index.html → src/sidepanel/index.tsx → src/sidepanel/App.tsx
```

与 popup **完全同构**（本模板两者 `App.tsx` 内容一致），仅入口 HTML 路径不同；Chrome 114+ 在侧边栏中以独立页面加载，同样享受 Vite HMR。

### 3.3 Content Script（`content_scripts[0].js`）

```
manifest.content_scripts.js: ["src/content/main.ts"]
        │
        ▼
src/content/main.ts  --[mountApp]-->  src/content/views/App.tsx (+ App.css)
        │                                   │
   创建 #crxjs-app 容器               Solid 组件，含 toggle 按钮与 HELLO CRXJS 弹窗
   render(createComponent(App))        样式需自隔离（见 05#CSS 泄漏）
```

- `main.ts:4` `console.log('[CRXJS] Hello world from content script!')` 用于验证注入成功
- `mountApp()`：`document.createElement('div')#crxjs-app → document.body.append → render`，满足 content script 无 HTML 的约束
- 匹配 `https://*/*`（生产建议收窄为实际域名，避免全网注入被商店审核质疑）
- 开发期由 `fileWriter` 通过 `content-dev-loader` 注入，支持 HMR（修改 `views/App.tsx` 无需刷新宿主页，见 `05#HMR 链路`）

### 3.4 共享层

| 路径 | 职责 | 引用方 |
|---|---|---|
| `src/components/HelloWorld.tsx` | 复用计数器组件，`props: { msg }` + `createSignal(0)` | `popup/App.tsx`、`sidepanel/App.tsx` |
| `src/assets/{vite,solid,crx}.svg` | 静态矢量资源，`import logo from '@/assets/crx.svg'` → `chrome.runtime.getURL`（content script）或直接 `<img src>`（popup） | 各 `App.tsx` |
| `public/logo.png` | 扩展图标，`manifest.icons[48] / action.default_icon[48]` 均指向它，经 `fileWriterPublic` 原样输出 | `manifest.config.ts` |

## 4. 构建产物（`npm run build` 后）

```
dist/
├── manifest.json                 # 已重写：popup/sidepanel/content 路径映射为 chunk 名
├── service-worker-loader.js      # 仅当启用 background 时（本模板当前无）
├── src/popup/index.html          # 含 hash 的 script 引用
├── src/sidepanel/index.html
├── assets/                       # js/css/svg 带 hash
└── src/content/main.ts.js        # content script 输出（由 pluginContentScripts 决定文件名）

release/
└── crx-sai-translate-1.0.0.zip  # 一键上传商店
```

开发期（`npm run dev`）额外在内存/dist 混合写入 `content-script-loader` 等中间文件，供 HMR 轮询。

## 5. 典型改动配方

| 需求 | 改哪 |
|---|---|
| 加 Options 页 | `manifest.config.ts` 加 `options_page: 'src/options/index.html'`，新建 `src/options/` 复用 popup 结构 |
| 加 Background | `manifest.config.ts` 加 `background: { service_worker: 'src/background/main.ts', type: 'module' }`，新建 `src/background/main.ts` 监听 `chrome.runtime.onInstalled` |
| 收窄 content 匹配 | `manifest.config.ts` 将 `matches: ['https://*/*']` 改为 `['https://translate.google.com/*']` |
| 注入 Shadow DOM 隔离样式 | 改 `src/content/main.ts#mountApp` 为 `attachShadow({mode:'open'})`，CSS 写入 shadowRoot |
| 动态脚本（MAIN world） | 新建 `src/injected.iife.ts` 或 `crx({ contentScripts:{ standaloneFiles:['src/injected.ts'] } })` |
| 换图标 | 替换 `public/logo.png`（48/128 建议各一套），`manifest.config.ts#icons` 同步 |
| 关自动重载 | `vite.config.ts` 改 `crx({ manifest, liveReload:false })` |

## 6. 已知约束与建议

- `side_panel` 需 Chrome 114+，低版本会忽略
- `permissions: ["sidePanel","contentSettings"]` 本模板已声明，前者为 sidePanel API，后者若未用可移除以减少权限警告
- `matches: ["https://*/*"]` 过宽，上线前务必收窄
- `vite-plugin-zip-pack` 的 `outFileName` 使用 `package.json#version`，发版前先改 `version` 再 `build`
